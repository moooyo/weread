# Physical font admission and installed Library entry

On November 20, on one **Kindle Scribe 2022 / firmware 5.19.5**, using the
bundled receipts reduced median elapsed time for the seven-face outline
admission loop from **2,709.496 ms to 3.557 ms**. All six warm pairs improved;
the median of the six within-pair differences was **2,705.946 ms**. This is
not the time to open the Library. No application or UI was launched.
The [raw samples and closeouts](physical-20261120.json) include the excluded
warmup; the older 9.820 s request-to-SEND result is not part of this batch.

## What ran

The [guarded ARM probe](arm-admission/probe.rs) was built on `test-env` from
the product's opt-in build declarations, immutable font bytes, static-slice
lookup and release dependencies. The [shared worker](rebuilt-worker.md) used
the locked source at `8f49fcb` (same product inputs as `7b41404`). QEMU
`--verify` first reproduced the [ARM accounting output](arm-admission/verification.txt).
There was one 64,502,220-byte probe, not two application launches. Each
sample timed all seven faces with `Instant`, a fresh budget and identical
final `FontUsage`. A complete pair warmed the process; six more alternated
the order, full path first in rounds 1, 3 and 5. No caches were flushed.

| Warm measured range | Minimum | Maximum |
| --- | ---: | ---: |
| Full outline admission | 2,699.487 ms | 2,717.518 ms |
| Receipt-assisted admission | 3.543 ms | 3.910 ms |

This says nothing about display submission, orientation queries, covers
arriving, an input event, or stable ink. Do not subtract this saving from a
different binary's request-to-SEND time or enable the feature by default on
the strength of this probe.

## Device ownership

The priority owner agreed to a CPU-only window. The [worker driver](arm-admission/cpu-batch.py)
used the pinned SSH transport and the existing owner/token lease on the
**host**, acquired immediately before operation. The [device script](arm-admission/cpu-stage.sh)
matched the first-generation Scribe hardware family and firmware without
recording a serial. The family check uses the public first-generation codes
in the [reviewed KOReader revision](https://github.com/koreader/koreader/blob/7c38cf104cb9ea89df243e47ec820ef4aa97cab8/frontend/device/kindle/device.lua#L2156).
It required an awake device with the stock framework in the foreground,
a running statusbar, a non-paused window manager, no reader/launcher lock,
and adequate memory and space on an executable user partition. Only a fresh
hidden `/mnt/us` directory was used. The probe armed
its parent-death guard and 120-second deadline or refused to produce samples.
There was no power request, input injection, framebuffer access or registry
operation. The owned stage was removed, native idle was checked again,
connections closed and the lease released at **16:18:09 Asia/Shanghai**.

## What the actual entry can select

A second, separately approved [read-only audit](arm-admission/entry-audit.sh)
found exactly one catalog row for `/mnt/us/documents/weread.sh`. The document
matched the [November 15 monolithic launcher](https://github.com/moooyo/weread/blob/5a66fe7bf8962ee0c950d5bd4af6c0b45e553578/packaging/kindle/launch.sh)
byte for byte. `/mnt/us/weread/app/weread` was a regular file; its contents
and identity were not checked. `/mnt/us/weread/launch.sh`, the separate
supervisor expected by today's wrapper, was absent. Only the exact public
document-path count was returned from a read-only immutable catalog view;
the audit skipped a nonempty WAL or journal and would discard the result
if the database changed during the query. No document, installation or registration
was written, and no private shelf was opened. Native idle was observed on
both sides; the separate lease was released at **16:21:21 Asia/Shanghai**.

The matched launcher chooses its app and data from `WEREAD_HOME`, normally
`/mnt/us/weread`. Its normal app command does not select the public offline
fixture or either staged binary. Setting an environment variable in an SSH
shell is not a verified way of passing it through the native file-open
service. Thus an ordinary request against today's entry would time the daily
app, not A/B. Direct shell execution with a different home would measure a
different starting point. Neither operation was used to invent a shelf result.

**Remaining decision:** preserve the existing document and installation.
A separately named temporary indexed test document could select the same
isolated stage for both arms. It would create and later remove a catalog
item and measure that **test entry**, not the installed daily entry. It
needs explicit approval, a frozen peer/registration protection baseline,
staging and cleanup rehearsal, and a fresh UI window. No such item or
selector was installed. If the daily entry itself is required, first approve
a routing mechanism for that specific entry; do not shadow the live
installation, silently rewrite the document or reopen the private shelf.

The operator subsequently approved the separate temporary item and unattended
deployment after qualification. See the [indexed trial protocol](../../../tools/kindle-font-trial/README.md)
for that later work; the CPU-only result above remains a separate endpoint.
The [completed indexed measurement and normal deployment](indexed-font-ab-20261120.md)
now supersede the November 15 installed-launcher description above.

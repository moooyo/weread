# Stock tap with no bound GUI

A confirmed stock-card release does not prove that the native dispatcher has
already run the selector. Idle native UI and the absence of a WeRead process
also cannot prove consumption. Never erase an intent, click again or stop a
process by name to close this case.

For an otherwise unknown launch, close can disarm **this selector** under the
same private file lock that protects its entry decision. A selector callback
that actually ran records its batch, PID and process birth. It records a
decline only if it never wrote `selector-entered`; before a successful exec
the entered path removes the decline handler. A closed visit needs one such
matching, retired callback; a confirmed raw tile release from this visit; no
extra callback, group, GUI session, request or live input channel; and two
consistent native-idle/protected-state checks. The final close independently
rechecks those facts in addition to the regular launcher restoration. It does
not create a startup timing, a GUI identity or a successful launch result.

An unconsumed request, a foreign/live process, a changed native state, an
unconfirmed input release and a selector that already entered but has no
bound process all remain unproven. In particular, the absence of any callback
is not permission to remove the overlay: a late handler could then open the
ordinary installation. Only a positively identified trial uses the normal
owned-supervisor shutdown. No part of the declined path signals a process.
